{# Reverse Engineering mode's Start/Pause/Stop/Resume/Re-scan control bar. Extracted into its own partial (not inlined in session.html) so the SAME markup is both the initial page render AND the target of htmx's own polling re-fetch below -- exactly the pattern re_triage_stage.html already uses for the chat pane. Real, confirmed incident this fixes: the control bar used to be a static block that only rendered on a full page load. While a baseline triage pass ran, it showed Pause/Stop; when the pass then finished on its OWN in the background, nothing re-rendered this block, so the now-meaningless Stop button kept hanging there until a manual reload. Clicking that stale Stop hit the (idempotent) stop route on an already-completed session -- see main.py's re_triage_stop for the other half of this same fix. hx-trigger="every 3s" while pending/processing re-fetches this exact partial; the moment status flips to a terminal state the response comes back WITHOUT that trigger (only the pending/processing branch carries it), so htmx naturally stops polling -- same self-terminating mechanism as re_triage_stage.html. Every button below is still a plain (non-htmx) form submit whose route 303-redirects back to this page, so a click always reloads the whole page fresh and restarts polling as appropriate -- the poll only has to survive long enough to catch a background self-completion, which is the exact failure case above. #}
