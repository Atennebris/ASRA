{{ section_label("Reserve providers (fallback chain)") }}

Off by default. Today, if the provider/model above fails mid-scan (an outage, a quota limit), ASRA simply stops and reports the error — it never automatically switches to another configured provider on its own, so it can never spend a paid provider's tokens/money you didn't explicitly authorize as a reserve. Turn this on to define your own ordered backup list instead: try the next model on the same provider first, then move to the next provider once every model there is exhausted — as many providers and models as you want, in whatever order you want. Applies to delegated subagents too, not just the main agent — both go through the same reserve chain once it's on, no separate setup needed per subagent.
